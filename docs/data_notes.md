# Data notes: original data, synthetic supplement and known discrepancies

All data in this repository is fictional demo data. The 13 CSVs in `Data/` are the original sample set and are never
modified. `Data/supplementary/` is a deterministic synthetic overlay generated by
`scripts/generate_supplementary_data.py` (fixed seed 20260904; running it twice gives byte-identical files; the script
checks the SHA-256 of the originals before and after). The loader inserts overlay rows only where the natural key does not
already exist, flags them `is_synthetic = 1` and leaves every original row (flag 0) untouched. Set `MSIM_USE_SUPPLEMENT=0`
to load the originals only. Every golden result (Q1-Q10, Q4F) is identical with and without the supplement; this is tested.

## What the supplement adds, and why

| Table | Rows added | Rule | Enables |
|---|---|---|---|
| `fact_nav` | 104 | Smooth backward path from the original 2026-09-04 row for every business day 10 Aug - 3 Sep (F004 only missing days). Status `Final` | AUM trend and decline questions for every fund |
| `fact_cash_balance` | 104 | Same dates; AUM equals the NAV row; cash % mean-reverts towards the 2026-09-04 value | Cash-percentage history |
| `dim_date` | 208 | Missing calendar dates (weekends) in 2025-01-01..2026-12-31, `is_business_day = 0` | Date coverage incl. 2026-09-05..07 |
| `fact_revenue` | 72 | Per fund 2025-09..2026-07 (interpolated between the original 2025-08 and 2026-08 rows) and 2026-09 month-to-date | Revenue trend questions |
| `fact_flows` | 18 | Per fund 2026-05..2026-07, scaled from the 2026-08 values | Flow momentum questions |
| `fact_flow_detail` (new) | 263 | 3-6 subscription and 3-6 redemption lines per fund-month; amounts sum EXACTLY to `fact_flows` | Largest single redemption, flows by investor type |
| `fact_sla_history` (new) | 570 | One completed record per fund, process and business day before 2026-09-04, with a `breached` flag | SLA adherence and missed-SLA questions |
| `fact_recon_break` | 24 | Resolved breaks BRK101..BRK124 with `open_date` and `resolved_date` (added column `resolved_date`) | Open-break counts over time |
| `dim_fx_rate` (new) | 249 | Daily 2026-08-01..2026-09-30 plus first-of-month 2025-01..2026-12; one row per (date, ccy). USD 1.0, EUR 1.08, GBP 1.27 | USD-equivalent totals with an explicit label |

`fact_settlement` and `fact_transaction` are not touched: the 632 trades are the golden basis.

## How golden results are protected

- Added `fact_nav` / `fact_cash_balance` rows are earlier than 2026-09-04 and `Final`, so `MAX(date)` and the 09-04 rows are unchanged.
- Added breaks are all `Resolved`; added flows months are 2026-05..07; added revenue months exclude 2025-08 and 2026-08.
- `fact_sla` and `fact_pricing_exception` are untouched; SLA history lives in `fact_sla_history`.

## Open-break semantics

`open on date d` = `open_date <= d AND ((status = 'Open' AND resolved_date IS NULL) OR resolved_date > d)`.
BRK007/BRK008 (open dates 2026-09-05/06) are not open on 2026-09-04, so 6 breaks are open that day while
`COUNT(*) WHERE status = 'Open'` is 8. Original `Resolved` rows (BRK009, BRK010) have no resolution date and are
excluded from historical counts; inventing dates would alter original data.

## Known discrepancies between the playbook and the data

- D1 "yesterday": the playbook anchor is Monday 2026-09-07 with "yesterday" = 2026-09-04. The app uses `AS_OF_DATE`
  (default = latest data date 2026-09-04) for snapshots and `YESTERDAY` = latest settlement date (2026-09-04).
- D3 Q4F value 11,050,000 adds USD and EUR amounts without FX. The app reproduces it and warns; a USD-equivalent figure is 11,420,400.
- D4 the "four-week average" is the pooled rate over all 20 settlement dates including yesterday (620/632 = 98.1%).
- D5 playbook uses short fund names ("US Core Bond"); the data has "MS US Core Bond Fund". Comparisons use fund_id or normalised names.
- D7 the Q10 pattern returns per-signal component columns in addition to the score so the narrative can explain it.
- D8 other oddities: BRK007/BRK008 `open_date` after the as-of date; `fact_settlement` has no Pending rows; 2026-09 flows are
  month-to-date (4 days) against a full 2026-08; `dim_date.month` is an integer while `fact_flows.month` is 'YYYY-MM' text.
